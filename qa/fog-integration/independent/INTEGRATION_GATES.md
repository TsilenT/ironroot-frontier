# Fog integration recommendation and next evidence gates

## Current recommendation

Keep the current evidence and public behavior bounded to QA-only Classic/open-ended/no-bridge. Desktop feasibility, exact optimization parity and the completed synthetic memory increment now justify a careful local main-app integration draft under the parent's permission; this is distinct from enabling the mode for users or releasing it. Phase one is frozen under `/workspace/shared/ironroot-fog-prototype-phase1-frozen`; its implementation and evidence should remain an immutable comparison point.

The completed increment provides actual desktop renderer evidence for frozen memory labels/clearing/replacement and reduces the measured crowded-combat Node step median by roughly 36%, with exact phase-one state/RNG/observation parity. These are bounded synthetic results; ordinary-match memory feel and browser/device performance remain open. Native mobile remains explicitly blocked by the browser's DevTools restriction; that denial is not authorization for another emulation route.

## Memory/performance milestones completed before local integration

1. **Exact optimization evidence.** Profile first. Preserve exact state, RNG, paid actions, AI decisions, memories and observable events against the frozen phase-one implementation. Cover both sides, direct commands within one tick, births/deaths, splash, event saturation and restore. Keep pre-combat contact eligibility separate from fresh event-birth/current visibility. A cache keyed only by tick is unsafe because build, sale, spawn and damage can change sight before that tick changes. Pooled arrays must not alias earlier detached observations. Report sparse and crowded workloads with counts and repeated timings; CPU numbers remain Node-only.
2. **Remembered-building presentation.** Obtain desktop evidence for seen building → lost sight → hidden change → re-observation. The minimum useful sequence demonstrates a dashed frozen type/level/time record, no current HP/production, no stale troop marker, and clearing or replacement on re-observation. Prefer ordinary paid play. If a reliable paid sequence is impractical, an explicitly labelled synthetic fixture using the real observation and renderer is valid mechanism evidence, not a claim of natural gameplay or balance. Pair screenshots with exact fixture/source identity and model assertions.
3. **Freeze and recheck the increment.** Keep the phase-one evidence intact. Record the final changed-file hashes, run affected suites plus required aggregate checks once the increment is stable, and distinguish any stale expectation repair from runtime changes. Recheck the native desktop flows affected by presentation or lifecycle edits. Do not silently promote an earlier screenshot to final-code evidence.

The sections below distinguish the work to design/implement from the verification still required before release.

## Work to complete before releasing normal Skirmish fog

### Production observation boundary

The existing main app is still a full-information consumer. Its field and minimap, every effect/projectile path, audio/music intensity, HUD, enemy citadel/options dialog, selection/inspection text, accessibility state, Front/follow and restored camera must use a side observation whenever the bound match has fog. The QA shell's success does not sanitize those existing paths. Retain authoritative paid commands privately; never forward a raw engine or serialize/action closure through the renderer façade. Reports/full reveal must remain terminal-only.

### Immutable rules and supported combinations

For a future authorized production promotion, decide and approve a deliberate immutable production identity; retain the QA identity's normal-codec fence. This review recommends that separation but does not authorize creating or admitting a production identity now. Do not repurpose a frozen experimental identity by changing what it means or silently migrate existing battles. A fresh-production fog match can remain Classic only, open-ended only, with bridge income off. Explain unsupported combinations and require an explicit compatible selection rather than silently changing map or rules. Fog remains default off. Restart preserves the bound rules; new ordinary battles and all existing campaigns/trials/practice remain unchanged.

### Save/profile/history contract

Normal resume, backup import/export and writer admission need an explicit fog-aware path with both sides' validated bounded memories. Verify deterministic continuation, stale memory lifecycle, malformed rejection without mutation, rule/map identity, profile concurrency and rollback behavior. Allocate the next appropriate profile-writer fence for older clients that cannot safely preserve the new identity/data; do not assume an unknown-rule error alone protects the shared storage slot. History and terminal reports should label the variant, while live reports cannot expose full hidden intelligence. A session-only setup preference is acceptable initially and avoids another persisted preference migration.

### Offline/release packaging

The current production asset/cache manifest is intentionally unprepared even though rulesets statically import the new module. A real release requires a complete cacheable asset/dependency bundle, a version/cache update, release-preflight success and cold-start/offline/update tests on the exact release build. Verify old tabs cannot mix old renderer code with a new fog save. Preserve the existing rollback/export recovery guarantees. Do not deploy the QA tree or bypass its release guard.

### Release validation gates, not prerequisites for local draft work

Complete permitted native checks at the requested short portrait, ordinary portrait, short landscape and desktop sizes when an authorized environment is available. Until then, mobile remains a disclosed open gate. Check touch cancellation/multitouch, minimap panning, build/Volley feedback, order cancellation, pause/interruption/resume, memory contrast without color alone, hidden citadel text and screen-reader descriptions. Run a full paid fog match and sustained crowded browser checks at normal/fast speed. These remain release performance/usability gates even if a local main-app draft has already been implemented; they are not proof of equal player/AI strength. Paired seeds and human play should then assess passivity, counters, scouting value and whether surprise feels understandable.

## Scope that can remain intentionally constrained

- Classic only; no Twin Span or Long March sight/road edge cases yet.
- Open-ended only; no timed objective/decay presentation policy yet.
- No bridge income combination until public beacon/contest disclosure is explicitly chosen and tested.
- No changes to existing authored missions. Future fog missions should be new explicit scenario/rules identities with public briefing intelligence and known objective locations.
- Known terrain, no exploration grid/occlusion/new scout/manual troop order system.
- Existing automatic flyers stay 300 acquisition / 420 retention.
- Conservative projectile omission/contact cues can remain a labelled prototype limit. Production combat readability needs evidence before deciding whether that compromise is acceptable.
- No saved fog preference is necessary for the first production increment if default-off/session-only setup is clearly presented.

## Current top risks

1. Future visibility caching or pooled mutable observations could introduce information/determinism regressions; this reviewed optimization avoids both and preserves exact parity.
2. A main-app checkbox without the full observation audit would expose hidden state through secondary UI/audio paths.
3. Save/profile/offline integration without a writer fence and complete versioned asset set could create unreadable or unsanitized resumed battles.
4. Dashed memories can pass model tests yet be misleading or unreadable during real play, especially on the currently unverified mobile layouts.
5. The longer controlled crowded fixture now shows roughly 36% lower step CPU than frozen phase one, but still roughly 2.38 times released no-fog CPU. This Node result is not browser/mobile FPS evidence; the earlier 3.1-times result used a different shorter fixture.
